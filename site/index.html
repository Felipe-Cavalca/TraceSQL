traceSQL

Você precisa de um registro da base remota na sua máquina. Só que esse registro depende de um cliente, que tem pedidos, que têm itens, que apontam para produtos… e fazer dump da base inteira não é opção.

You need one record from the remote database on your machine. But that record depends on a customer, which has orders, which have items, which point to products… and dumping the whole database is not an option.

O TraceSQL parte de um registro, segue as relações e gera um .sql só com o que está ligado a ele.

TraceSQL starts from one record, follows the relations, and writes a .sql with only what is connected to it.

um binário. sem dump gigante. só os relacionados.one binary. no giant dump. just the related rows.

From the record you picked, TraceSQL finds the tables connected to it. The rest of the database stays out.

The related rows, with the schema they need, become a single file in the target database's dialect.

Your local database gets just the slice: what you need to reproduce a bug, test a migration or seed an environment.

como funcionahow it works

      

        

          1 / 5
          
a base inteira
the whole database

          
Sua base remota tem dezenas de tabelas e milhões de linhas. Para reproduzir um problema você só precisa de uma fatia dela.

          
Your remote database has dozens of tables and millions of rows. To reproduce a bug you only need a slice of it.

        

        

          2 / 5
          
aponte um registro
pick a record

          
Informe tabela, coluna e valor. Ex.: orders, id, 10. É o ponto de partida.

          
Give a table, column and value. E.g. orders, id, 10. That is the starting point.

        

        

          3 / 5
          
siga as relações
follow the relations

          
Pais e filhos por foreign key, ou pelo padrão [tabela]_id quando não há FK. Limite a profundidade e ignore tabelas como _log.

          
Parents and children via foreign keys, or the [table]_id pattern when there are none. Cap the depth and skip tables such as _log.

        

        

          4 / 5
          
gere o SQL
get the SQL

          
O resto fica de fora. Sai um arquivo com CREATE TABLE IF NOT EXISTS e INSERTs no dialeto de destino: Postgres, MySQL ou SQLite.

          
Everything else stays out. You get one file with CREATE TABLE IF NOT EXISTS and INSERTs in the target dialect: Postgres, MySQL or SQLite.

        

        

          5 / 5
          
migre / importe
migrate / import

          
Rode o arquivo na base local. Com --new-ids, os IDs são regenerados e as referências entre tabelas continuam corretas.

          
Run the file on your local database. With --new-ids, IDs are regenerated and cross-table references stay correct.

Now it's up to you: move the knob or turn the _log filter off.

    # 1. baixe e dê permissão
$ chmod +x tracesql-linux-amd64

# 2. postgres remoto → .sql para mysql local
$ ./tracesql-linux-amd64 \
  --driver postgres \
  --host db.exemplo.com --port 5432 \
  --user app --database app \
  --table orders --record 10 \
  --depth 2 \
  --ignore-table-suffix _log \
  --new-ids \
  --output-driver mysql \
  --out ./orders_10.sql

# 3. importe
$ mysql local < orders_10.sql
